# Migrating from upstream book-to-skill

Upstream: https://github.com/virgiliojr94/book-to-skill (this fork's
baseline: commit `68888e9`, see UPSTREAM.md).

## What still works unchanged

- `book-to-skill <paths> [--mode ...] [--install-missing ...]` — the plain
  extraction path (writes `full_text.txt` + `metadata.json` to
  `$BOOK_SKILL_WORKDIR`) is untouched. Any invocation that doesn't start
  with a subcommand falls through to it.
- All upstream parsers, dependency handling, `--check`, and the upstream
  test suite.
- The package import path `book_to_skill` (the *distribution* was renamed
  to `source-to-grounded-skill`; imports did not change).

## What changed

| Upstream | Fork |
|---|---|
| Agent generates directly into a live skills root (`~/.claude/skills/...`) | Generation goes to `.book-to-skill/staging/<skill-id>/`; `publish` is explicit and gated |
| No security boundary on document content | Sanitisation + layered injection scan gate generation; generated output is scanned before publication |
| Free-form summarisation per SKILL.md | Claims ledger first; prose is downstream and citation-marked (`[SRC:...]`) |
| No review workflow | draft → security-cleared → source-verified → expert-reviewed → published, with claim-level approve/reject that survives regeneration |
| One generic conversion recipe | Ten declarative domain profiles |
| `pip install` may be prompted for extractors | Unchanged, but `convert` defaults to `--install-missing no` |
| No runtime dependencies | `pyyaml` (profiles, structure maps) |

## Migrating an existing generated skill

Skills generated by upstream have no ledger and no provenance; there is
nothing to migrate mechanically. Re-convert the source through the grounded
pipeline:

```bash
source-to-skill convert book.pdf --skill-id my-book --profile scholarly-book --output .
# host agent generates per the new SKILL.md
source-to-skill validate .book-to-skill/staging/my-book
```

Keep the old skill until the new one reaches `published`; the old one can
then be deleted or kept as `deprecated`.

## For scripts that shelled out to extract.py

`scripts/extract.py` still works. New automation should prefer
`source-to-skill scan` (security posture) and `source-to-skill convert`
(staging) — both return meaningful exit codes (0 proceed, 1 scan-fail,
2 blocked).
